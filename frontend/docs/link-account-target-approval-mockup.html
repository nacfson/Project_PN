Link account — target must approve

Mockup for replacing one-tap LinkAccountBanner with a two-sided flow: initiator proposes, target approves via central-auth magic link (15 min TTL), then link completes.

Principle: Initiator can only request. Target approves by completing the existing central-auth magic link email (same mailer / magic_link_tokens, 15 min TTL) — no separate PN OTP.
Current

Home banner → one tap → linked

Only the signed-in session consents. Target never sees or confirms the request.

Proposed

Propose → pending → target approve → linked

Same email discovery, but link stays pending until the other identity proves itself.

4. Target approval (central-auth magic link)

No PN OTP. Target completes the existing CreateMagicLink → mailer → /auth/callback flow. PN confirm requires an email session, not the pending Google session.

  • TTL: 15 minutes (shared with MAGIC_LINK_TTL)
  • PN calls POST {CENTRAL_AUTH}/api/auth/magic-link?rd=/link-approve?request_id=…
  • Approve is an explicit tap after redirect (avoid email-prefetch auto-confirm)
  • Optional later: purpose-specific email copy in central-auth
