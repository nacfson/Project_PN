IMPLEMENTATION PLAN CONTRACT_AUTH_DOOR §3.4 Spec 009 BFF Logout

BFF Logout Revocation Status & Error Forwarding Plan

Executive Summary

All five nacfson_pipeline contracts (CONTRACT_AUTH_DOOR.md, session-revocation.md, gateway-internal-auth-api.md, shared-verification-module.md, and transit-signing.md) enforce a single synchronous revocation invariant: POST /api/auth/logout MUST return 200 OK {"status":"revoked"} only when the internal gateway confirms that Keycloak deleted the session (204/200), and MUST forward 502 Bad Gateway or 503 Service Unavailable unchanged without claiming revocation or wiping the client's bearer v1.<session_handle>.

Interactive Logout Revocation Flow Simulator

Select a Keycloak / Gateway outcome to inspect the required BFF & Frontend behavior.

[VERDICT: 200 OK {"status":"revoked"}]
1. Gateway authenticates as session-revocation-client and sends DELETE /admin/realms/platform/sessions/{sid}.
2. Keycloak returns 204 No Content; Gateway responds 200 OK {"status":"revoked"}.
3. PN BFF verifies status == "revoked", clears cookies, and returns 200 OK {"status":"revoked"}.
4. PN Frontend clears sessionStorage; next request with the old handle is rejected with 401.
